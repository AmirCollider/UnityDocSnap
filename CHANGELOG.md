# Changelog

All notable changes to Unity DocSnap are documented in this file.

## [0.9.1] - 2026-07-25

### Fixed

- **A lost manifest could delete a previous export.** `PruneStaleOutput` keeps each managed output folder holding exactly the files the manifest describes, and deletes anything it does not recognise. Its authority to do that rests entirely on the manifest being the tool's complete memory of the project — and that memory lives in `Library/UnityDocSnap/manifest_state.json`, which is machine-local, git-ignored, and the first thing anyone deletes to make Unity behave. `Load()` answers a missing or corrupt file by handing back a blank state and carrying on, which is right for every other caller and catastrophic for this one: a manifest describing one Scene arriving at a version folder holding twenty made the other nineteen Scenes' pages, data JSON and summaries all "unrecognised", and all deleted. The existing ownership guard could not help — the folder genuinely *is* a DocSnap version folder, which is exactly why it had something worth losing in it. The manifest now records whether it was actually read back from a prior run, and the pruner does nothing at all when it was not, saying so in the console. The version folder is the artefact the user keeps; nothing else in the tool can put it back.
- **Thumbnails accumulated forever.** `theme/thumbs/` was the one managed output folder the cleanup sweep never touched, and the only one that was purely additive: a preview was written as `<guid>.png` and nothing ever removed it. Re-exporting onto a version folder — which **Update Previous Export** does by design, repeatedly — therefore kept a preview for every asset the project had *ever* held, including every one since deleted, renamed or excluded. Nothing links to them, so the folder simply grew, invisibly. The asset index already carries one entry per exported asset keyed by the same GUID, so it is now the live set. A Scene-only export, whose asset index is untouched and empty, deliberately skips the sweep rather than reading "empty" as "none of these are current".
- **Exporting during Play Mode is refused.** An export opens every Scene, and in Play Mode that runs `Awake`/`OnEnable`/`Start` on everything it opens *inside the running game*, while documenting the live simulation — runtime-spawned objects in the hierarchy, serialized values already mutated away from their authored state — rather than the project. Neither half is what anyone asked for, and the first can damage a session in progress. An export started while compiling or importing is refused for the milder version of the same reason: types are being swapped underneath the reflector and the AssetDatabase is mid-write. Both say plainly what to do instead, in all three languages.
- **A custom logo is no longer inlined as markup.** An SVG logo's contents were pasted into every exported page verbatim. SVG is not an image format in the way PNG and JPEG are — it is an XML document that can carry `<script>`, event-handler attributes and external references — so inlining one handed the exported page arbitrary control over itself. The file is the user's own, which makes the practical risk small, but a logo can arrive from a brand kit, a contractor or an asset pack, and the page it lands in is the page a whole team opens. Every format now takes the same route the raster ones already did: a `data:` URI inside an `<img>`, where the browser renders the same picture with scripting and external loads disabled by spec. WebP was added while the format list was being touched.

### Changed

- **The generated site's CSS, JS and fonts are real files again.** They lived in C# verbatim strings: `DocSnapFontAssets.cs` was 582 KB and `DocSnapSiteAssets.cs` 98 KB, together about half of the entire codebase, in a form no C# tool could see into — no linting, no syntax highlighting, no formatter, and every literal double quote written twice. `DocSnapSiteAssets` even carried a note reading "the readable sources they were authored from are plain style.css / app.js; keep the two in step", a manual synchronisation obligation against files that were **not in the repository at all**; there was no way to check it had been honoured and no way for a contributor to find the other half. They now live in `Editor/UnityDocSnap/Site~/` as `style.css`, `app.js`, `fonts.css` and `logo.svg`, read at export time through the new `DocSnapSiteFiles` and cached per domain reload. The trailing `~` is deliberate: Unity ignores such folders completely — no import, no `.meta`, no guessing which importer a `.css` or a `.js` should get — while UPM still ships them exactly like the standard `Documentation~` and `Samples~`. Output is byte-for-byte identical to 0.9.0. Two source files shrank from 680 KB to 4 KB.
- **`preview-sample.html` moved to `Docs~/`.** At the package root it carried a `.meta`, so Unity imported 710 KB of sample output into every project that installed the tool. `Docs~` is invisible to Unity and still ships in the package.

### Added

- **Continuous integration.** `.github/workflows/ci.yml` validates the package on every push with no Unity licence and no secrets — so a fork and a pull request get the same answer the maintainer does — checking version agreement across `package.json`, `DocSnapConstants.Version` and this changelog, `.meta` coverage and GUID uniqueness (a script shipped without its `.meta` gets a fresh random GUID in every user's project, and the author never sees the problem their users get), and that the site assets the exporter reads at runtime actually ship. The EditMode tests then run in a real Editor against Unity 2021.3 (the declared floor) and Unity 6, in a minimal host project assembled around the package. That job checks for the licence secret first and reports "skipped" without it, so a red X always means a real failure.
- **Tests for the code that deletes files.** `PruneStaleOutput` was the only code in the tool that deletes anything, and the only part with no tests at all — which is how the manifest bug above stayed a bug. Ten cases now cover the fresh-manifest refusal, the normal sweep, the ownership guard, thumbnail pruning and its empty-index exception, and the project-wide files that must survive a single-item export. `DocSnapSiteFilesTests` covers the new file-backed site assets, since a missing file is a failure mode a string constant did not have.
- **A release workflow.** The package advertises installation from a git URL, and UPM resolves a version by tag — with no tags in the repository, every user got whatever the default branch happened to be that day, could not pin a known-good release, and could not roll back from a bad one. Pushing a `v*` tag now publishes a GitHub Release with notes taken from this file, and fails if the tag and `package.json` disagree.
- `.gitattributes` and `.gitignore`: LF normalisation so a Windows and a macOS contributor stop producing whole-file diffs, and the base64 fonts and sample page marked `linguist-generated` so GitHub's language stats describe the tool rather than its assets.

### Documentation

- **The Output Structure section described a layout the tool stopped producing.** It showed `index.html` at the output root as "the full offline site (start here)". Since versioned exports arrived, the root holds only a redirect and `versions.html`, and the site itself lives in `V1.0.0/`. `versions.html`, `changes.html`, `export-info.txt`, `changes-files/` and the backup were absent entirely, and the only mention of versioning anywhere in the README was a ticked Roadmap box. Rewritten in all three languages, with the version shelf and one version folder shown separately.
- A Contributing section covering where the site assets now live, the validation script to run before opening a PR, and how a release is cut.
- The manual-install steps now mention the `Site~` sub-folder, which a hand-copy must include.

## [0.9.0] - 2026-07-25

### Added

- **The cozy skin is back, as a skin.** The pastel gradients, generous radii, soft shadows, rounded display face and bobbing boba mascot are the tool's signature, and 0.8.0 traded all of it for speed. Both looks now ship: **✨ Cozy** and **⚡ Lite**, switchable in the sidebar and remembered. Which one an export *opens* with is measured rather than assumed — `DocSnapCapability` reads the exporting machine's RAM, core count, GPU and GPU memory (and flags software renderers like llvmpipe/SwiftShader), then weighs the project itself, because cozy's cost is per rendered row and it is a 40,000-object Scene that decides, not the CPU. Pass every check and the site opens cozy; fail one and it opens lite **and says which check failed, with the numbers**. The browser re-checks against the machine actually reading the page (`navigator.deviceMemory`, `hardwareConcurrency`, `prefers-reduced-motion`) and may downgrade further — the reader is often not the exporter. A reader who turns cozy on against that verdict gets it, plus a panel listing every measurement behind the recommendation, because a warning with no numbers is a shrug. `Project Settings ▸ Unity DocSnap` and the export window both offer **Auto / Cozy / Lite** to skip the heuristic entirely. The mascot's animation is transform-and-opacity only (a compositor job that never touches layout), the hover lift is confined to things a reader points at deliberately and never applied to a tree node, and everything stops when the OS asks for reduced motion.
- **The health report separates your files from Unity's.** A project reporting eight findings — seven in `Assets/Settings` (the render-pipeline assets a Unity template creates) and one in `Assets/TextMesh Pro` — has nothing for its author to do, and none of it can be edited or deleted. Every finding is now classified `mine` or `vendor` by path, with a **My files / Unity & packages / All** tab defaulting to *My files*, and the vendor rows naming the folder that made them someone else's problem. The dashboard leads with the count that is actually yours: a project whose only findings are vendor ones now reads as clean there and names the rest below, instead of opening with "8 broken references" that nobody can act on. `summary.md` marks them `_(not yours)_` so an assistant does not go trying to fix TextMesh Pro. Unity's own install locations (TextMesh Pro, Settings, Samples, XR, XRI, Plugins, Standard Assets, TutorialInfo, Editor Default Resources, Gizmos) are built in; a project can add its own vendor folders in Project Settings. Matching is on a path boundary, so `Assets/SettingsUI` stays yours.

### Fixed

- **Files nobody had touched stopped being reported as modified.** `Assets/TextMesh Pro/Resources/Fonts & Materials/LiberationSans SDF - Fallback.asset` appeared under **Modified** on nearly every Changes page, because the snapshot fingerprint was size + last-write time — which answers "did the filesystem touch this?", a different question. Unity re-stamps the assets it manages on its own schedule, and TMP rewrites that fallback whenever the dynamic font atlas renders a glyph. Each file now also carries a hash of its actual bytes, and that is what the diff compares. Computed only when the cheap signature says something may have moved, so an unchanged file's hash is reused with **zero disk reads** and a repeat export costs nothing; files over 128 MB keep the timestamp fingerprint. Snapshots recorded before this release have no hashes, and the diff falls back to the old comparison for those rather than declaring every file in the project modified once during the upgrade.
- `border-style: dashed` in the cozy skin activated all four borders at their `medium` default width, drawing a 3px box around the sidebar footer instead of a rule above it.

## [0.8.0] - 2026-07-25

### Added

- **Project health now tells you *where*.** The dashboard said "8 broken references in Assets" and linked to the Assets page — which on a real project is thousands of rows long, so a reader learned a number and then had to go hunting anyway. Every finding is now recorded individually with the GameObject path it sits on (`Canvas/Menu/StartButton`), the component and field that hold it (`MenuController › targetScene`, `PathFollower › waypoints[3].marker`), and the anchor of the card that renders it. A new **`issues.html`** lists them all, each row a link that opens the collapsed section it lives in, scrolls to it, and flashes it so the arrival is visible. Findings inside a Prefab asset are labelled with the Prefab (`Player.prefab › Body/Hand`) and pinned to that Prefab's card. The dashboard's counts became links into the report pre-filtered to their own kind, and every scope row links to the report scoped to that Scene/folder instead of dumping you on the page. **Health** has its own sidebar entry with a live count. The same detail lands in `summary.md` (so an assistant asked "why is the menu button dead?" can answer) and in `data/manifest.json`. Capped per scope at 400 findings, and a capped scope says so instead of quietly disagreeing with the count above it.
- **An in-page filter on every tree.** The sidebar search jumps to one record on some page; this narrows *this* page to the rows that match, keeping each match's ancestors so the path stays readable and collapsing their detail bodies so the match is not buried under a screen of fields. On a folder with thousands of assets, or a Canvas holding 300 buttons, it is the difference between scrolling for a minute and typing four letters.
- **Breadcrumbs** on every Scene and folder page, so a page reached from a search result or a cross-link says where it sits and offers the way back out.
- **A collapsible sidebar** (the `«` button, or `[`), remembered per reader — on a 13" laptop the field tables want the width more than the nav does.
- **Copy path / Copy GUID** on every asset card. The asset path is the most-copied string in the whole site and the only way to get it was to select it out of a table cell by hand.
- **Arrow-key navigation in search results**, so the fastest route to any object in the project no longer ends with reaching for the mouse.

### Changed

- **The generated site was rebuilt around finding things in a large project.** The old stylesheet dressed every surface — gradient card headers, 22px radii, a lift-on-hover shadow on every row, a pastel wash behind the sidebar. On a small demo that reads as charm; on a real project it is thousands of decorated rows between a reader and the object they came for, and every one of those decorations is layout and paint work the browser does before the page responds. The rebuild keeps the brand where a person looks once (the mark, the accent, the empty states) and gets out of the way everywhere a person looks a thousand times: flat surfaces separated by 1px borders, one accent colour instead of four pastels, a tighter type scale, a denser and calmer information layout in both light and dark.
- **Large pages are dramatically lighter.** `content-visibility` now applies to every repeated block — each tree node, each GameObject detail body, each component card, each issue row, each diff row — so a Scene with 20 000 GameObjects no longer makes the browser lay out 20 000 rows before it paints anything, with `contain-intrinsic-size` keeping the scrollbar stable while it works.
- **Text renders in the OS's own UI font first.** The embedded families stay in the stack as an offline-identical fallback (so the export is still fully self-contained and makes zero network requests), but on any normal desktop the text is now the face the system renders best.
- The root `versions.html` picker was restyled to the same tokens, so the first page you open and the site it leads into no longer look like two different products.
- `preview-sample.html` regenerated from the real `theme/style.css` and `theme/app.js`, with sample health findings, working filters and working deep links — it is the shipped site, not a picture of it.

### Fixed

- **A rejected version name could still produce a folder with a different name than the one shown.** `Path.GetInvalidFileNameChars()` is the whole check the runtime offers and on Windows it is not enough: a name ending in `.` or a space is silently trimmed when the directory is created, so `V1.` became a folder called `V1` while the registry, `versions.html` and every link kept saying `V1.` — and the next real `V1` then collided with it. Reserved DOS device names (`CON`, `NUL`, `COM1`, …) are rejected too; creating one fails outright, so an export used to die at the very last step with an unexplained IO error.
- **`SerializedProperty` array elements were still leaking.** 0.7.0 disposed the `SerializedObject`s and the iterators but not the properties `GetArrayElementAtIndex` hands back — one per element of every array on every component, importer and ScriptableObject, which is the densest allocation site in the whole export.
- A `data-copy` button's label is restored as markup rather than flattened to text, so copying a path no longer leaves that button stuck in one language for the rest of the session.
- A deep link whose anchor is the `<li>` *wrapping* a collapsed node now opens that node too, instead of landing on a row that is still shut.

## [0.7.0] - 2026-07-24

### Fixed

- **Two Scenes with the same file name no longer overwrite each other.** `Assets/Levels/Main.unity` and `Assets/Test/Main.unity` both wrote `scenes/Main.html`, `data/scene-Main.json` and `summary/scene-Main.md`, so whichever exported second silently replaced the first — while the sidebar showed two "Main" entries pointing at the one surviving page, and both Scenes shared a single search-index scope so re-exporting one wiped the other's records. Output file names now come from a new `DocSnapNaming.SceneKey`, which keeps the plain readable name (`scenes/Main.html`) whenever it is unique in the project and appends a short stable hash of the Scene's path when it is not. The manifest records `sceneKey` alongside `sceneName`; state written by an older version is migrated on load, so previously exported pages keep resolving.
- **Folder keys could collide the same way.** `Assets/UI/Menu` and `Assets/UI_Menu` both flattened to `UI_Menu`. Flattening is only injective while no path segment already contains `_`, so an ambiguous path now carries a hash suffix and every ordinary folder keeps its friendly key.
- **A deep hierarchy took the whole Editor down.** Every other recursion in the tool was capped, but the GameObject walk was not: a deep enough chain (a generated bone rig, a procedural tree) threw `StackOverflowException`, which .NET cannot catch — so every `try`/`catch` around an export was powerless and Unity simply vanished. The walk is now capped at `MaxHierarchyDepth` and marks the node it stopped at; the search index, the anchor map and the health scan were rewritten as iterative walks for the same reason.
- **`Update Previous Export` could not see a renamed file.** The folder fingerprint was file count plus newest modification time, and renaming a file changes neither — so an update reused the entire asset pass and served documentation still describing the old name, with nothing to tell the user. The fingerprint now includes a hash of the file list.
- **A single-Scene export corrupted the version's recorded metadata.** Finalising with fresh defaults rebuilt the version snapshot as if the small export were the whole thing: a version made with *Include file copies* and a `.unitypackage` backup afterwards reported `Included file bytes: no` / `Project backup: no` in `export-info.txt`, lost its 📦 badge on `versions.html`, and dropped the Changes link from the dashboard — while `source-files/`, the backup and `changes.html` all sat untouched in the folder. Facts a run does not re-establish are now carried forward, and a single-item export re-renders in the version's own language and theme instead of resetting to English + light.
- **The reflector truncated nested objects silently.** A struct or `[SerializeReference]` field with more than 1000 members stopped at a bare `guard > 1000` with nothing in the output to say the object was partial — while arrays a few lines away correctly set `truncated`. Both now report it the same way, alongside a `fieldCount`.
- **HDR colours were documented as their dimmed LDR twins.** `ColorUtility.ToHtmlStringRGB` clamps to 0–1, so every emissive tint and bloom-driving light colour lost the intensity that made it interesting. The hex stays for the site's swatches; the exact channel values now travel beside it as `rgba`, flagged with `isHdr` and Unity's own `hdrIntensity` when they leave the displayable range.
- **`NaN` and `Infinity` were written as the number `0`.** A Unity float field genuinely can hold `Infinity`, and reporting it as zero is a documentation tool inventing a value the project does not contain. They are written as `null` now, which every renderer already reads back through `AsNumber(fallback)`.
- **Links broke on ordinary file names.** Half the site built hrefs through `EncodeUrlPath` and half concatenated the raw manifest value into `href="…"`. Those raw ones broke on any Scene or folder whose name contained `&`, `#` or a space — and a name containing a double quote (legal on macOS and Linux) escaped the attribute entirely. Every link now goes through one `HtmlPageBuilder.Href`.
- **HTML escaping was used inside `<script>`.** A browser does not decode entities there, so the value the boot script read differed from the same value read out of the matching HTML attribute — and those two are compared to decide whether a reader's stored language/theme belongs to this export. A proper `JsString` escaper replaced it.
- **One unreadable folder produced an empty export.** `Directory.GetFiles(…, AllDirectories)` abandons the whole enumeration on the first permission error, followed symlinked asset folders into unbounded loops, and counted hidden / `Foo~` / `cvs` folders that Unity itself never imports — so the totals disagreed with the Project window and the change diff listed phantom files. All three filesystem walks now share one `DocSnapFileScan` that skips what it cannot read, caps depth, and honours Unity's own rules.
- **Muting the console leaked.** Call sites set `Debug.unityLogger.logEnabled` directly, so a nested mute restored logging to "on" while an outer one still wanted it off — releasing exactly the warning being suppressed. `DocSnapLogGuard` counts nesting, and every export force-restores the console on the way out so it can never be left silently disabled.
- **Clicking the selected radio button in the export window flipped to the other option**, because both toggles read their return value straight back into the same field and `GUILayout.Toggle` unchecks an already-checked toggle.
- **A rejected custom version name fell through to auto-numbering in silence.** Typing `v1/2` produced a folder called `V1.0.3` with no explanation. The window now says why, both live and before the export starts.
- **`DocSnapConstants.Version` had drifted two releases behind `package.json`** (0.6.2 vs 0.6.4), so every generated `manifest.json`, `export-info.json`, summary footer, dashboard badge and the About window reported the wrong version. A new `PackageVersionTests` fails if the two ever disagree again.

### Performance

- **The preview wait is now budgeted.** Unity renders asset previews asynchronously, and the exporter polled for up to 400 ms **per asset** on the main thread — a project with a few thousand non-image assets could spend well over half an hour inside `Thread.Sleep` with a frozen Editor that looked crashed rather than slow. Waiting now draws down one shared per-export budget; once it is gone the export runs at full speed and falls back to type icons.
- **Assets are loaded once instead of up to three times each**, and unused assets are released every 250 files, so a full export no longer holds the entire project in memory at once.
- **`SerializedObject` and `SerializedProperty` are disposed.** A full export builds tens of thousands of them — one per component, importer and ScriptableObject — and none were released.
- Parsing a data JSON is no longer O(n²) in an object's member count, reading `.Items` on a non-array no longer allocates a list every call, and a script's line count no longer allocates one string per line.

### Added

- **Exports can be cancelled.** Both passes show a cancelable progress bar — the Scene pass previously showed nothing at all, so the slowest half of an export happened behind a completely frozen Editor with force-quitting as the only way out.
- **Exclude rules** (Project Settings ▸ Unity DocSnap, or the export window). One line — `Assets/Plugins` — removes imported Asset Store content from the file walk, the folder tree, the search index, the change diff and the counts at once; `*` and `?` wildcards are supported. What was excluded is stated on the dashboard, in `summary.md` and in `manifest.json`, because an omission nobody is told about is worse than no omission.
- **Only Scenes listed in Build Settings.** Opening a Scene is the most expensive single thing an export does, and mature projects are full of test beds, sandboxes and sample Scenes nobody wants documented.
- **A project health card on the dashboard**, plus a matching section in `summary.md`. Every export already walked past each Missing Script and each object reference whose target no longer exists, wrote both faithfully into the JSON, rendered them thousands of rows down a Scene page — and then said nothing. The counts now lead, link straight to the pages holding them, and a clean project gets a one-line all-clear.
- **`summary/ai-bundle.md`** — every summary in the export concatenated into one document, so a whole project is a single paste into an assistant instead of a folder handed over a dozen files at a time.
- **Keyboard shortcuts in the generated site:** `/` or `Ctrl`/`Cmd`+`K` focuses search, `Escape` leaves it.
- **`PruneDir` now refuses to run anywhere it cannot prove it owns.** It is the only code in the tool that deletes files.
- Tests for naming, versioning, exclude matching, health scanning and the package version — five areas that previously had none, including the file-deleting prune path and the version roll-over.

## [0.6.4] - 2026-07-23

### Fixed
- **A fresh export now always opens with the language/theme chosen in the export window.** The 0.6.1 fix reset a reader's stored language/theme only when the new export's *defaults differed* from the recorded ones — so re-exporting with the same defaults (e.g. Japanese + light again) kept opening with whatever language/theme had once been clicked inside the site itself (saved in the browser's `localStorage`, e.g. English + dark), which looked exactly like the chosen defaults being ignored. Every export run now bakes a unique stamp into its pages (`<html data-export>` / `window.__DOCSNAP_EXPORT__`); the first time a browser opens a page from a run it has not seen before, the stored choices are reset to that run's defaults. Choices made while viewing the *same* export are still remembered across pages and reloads, and a record left by an older DocSnap version is migrated automatically (its stamp-less format never matches, so the new export's defaults win).

## [0.6.3] - 2026-07-23

### Fixed
- **The generated site is now genuinely offline.** `theme/style.css` pulled its fonts from the Google Fonts CDN through an `@import`, so a site opened without a network connection silently dropped to system fonts and lost its branded look — despite the export being described as self-contained and offline. The Latin faces (Baloo 2, Quicksand, Space Mono) and the Persian face (Vazirmatn) are now embedded directly in the stylesheet as base64 `woff2` (only the weights the stylesheet actually uses, each keeping its original `unicode-range` so per-glyph fallback still works), so an export renders identically with **zero network requests**. Japanese uses a high-quality system font stack (Hiragino Maru Gothic / Yu Gothic / Meiryo) instead of baking a ~2 MB CJK face into every version folder. `preview-sample.html` embeds the same fonts. Fonts live in a new `DocSnapFontAssets` and are prepended to `DocSnapSiteAssets.StyleCss`.

## [0.6.2] - 2026-07-23

### Added
- **Downloadable files on the Changes page.** Every listed file now carries download chips: the file **as it is in this export** (copied from the live project into `changes-files/new/`) and — when the compared version was exported with *Include file copies* — the file **as it was in that version** (copied from its `source-files/` into `changes-files/old/`), so a modified file can be reviewed side by side. Added files offer the new copy, removed files the old one, modified files both. The version folder stays fully self-contained, `changes-files/` is rebuilt from scratch on every diff, and when the base version stored no file bytes the page says so explicitly instead of silently offering nothing.

### Fixed
- **No more RTL/LTR flash on load.** The page's direction, language and theme came from the exporter's defaults baked into `<html>`, while the reader's own stored choice was only applied at `DOMContentLoaded` — so a reader viewing an RTL-default export in English watched every page (worst on the heavy Assets page) render right-to-left for a moment and then flip. A tiny boot script in `<head>` now applies the effective language/direction/theme **before the body is parsed**; visible text is pre-rendered in the export's default language (not always English), the sidebar's active language button / theme icon / search placeholder match the defaults, and when a stored choice still requires a text swap the body stays hidden until the swap lands (with a 1.5 s failsafe so the page can never stay blank).
- Fixed a stray Japanese katakana character (`ル`) that had slipped into the Persian word «فایل‌ها» on the Changes page.

## [0.6.1] - 2026-07-23

### Fixed
- **The exporter's chosen default language/theme now actually shows up.** A language/theme stored in `localStorage` while viewing an *older* export (or simply the older export's own defaults, saved on first visit) silently overrode every newer export's defaults forever — exporting with Japanese + light still opened in English + dark. `app.js` now records which defaults each export was made with; whenever they change, the stored reader choices are reset to the new defaults. A choice made while viewing the *same* export is still remembered.
- **Duplicate dashboard stats.** The dashboard showed two overlapping stat rows ("Scenes / Assets / Packages / Updatable packages" on the Export Info card, then "Scenes exported / GameObjects / Asset folders / Files tracked / Packages" right below, with the same numbers under different labels). There is now exactly one stat grid; the Export Info card carries only the per-export facts (version, timing, file copies, backup, changes base).
- **Links into collapsed content now work.** Cross-reference chips and search results pointing at an asset / GameObject / folder anchor inside a closed `<details>` could not scroll anywhere (a closed `<details>` is never laid out). The site now opens every `<details>` on the path to the link target, then scrolls to it.
- A corrupt stored language value could throw inside `querySelector` and break every event wire-up on the page; stored values are now validated against the real buttons instead of being interpolated into a selector.
- Removed a duplicate `using System;` in `FieldRenderer`.

### Changed
- **The Assets page is now light even in Advanced mode.** Every asset card is a collapsed `<details>`: closed, it is one compact header row (name + type + file size); opening it reveals the full info, and the open card takes the full row width so its tables have room to breathe (this also fixes cards whose content overflowed and overlapped). Combined with `content-visibility: auto`, a folder with hundreds of files lays out a light list instead of hundreds of full cards.
- **Expand all no longer freezes the page.** It now expands only the tree nodes themselves (folders / GameObjects), never the per-item heavy detail (asset cards, Import Settings, Fields, Prefab Contents). Collapse all still closes everything.
- **The whole-project `.unitypackage` backup runs last and warns first.** The export window now shows a trilingual warning (very heavy operation — save your project first) before an export with backup enabled, and the backup is built only *after* the complete site is already on disk, so a failure or crash during the backup can never damage the documentation export. `export-info.*`, the dashboard and `versions.html` are refreshed afterwards to reflect the backup.
- **Richer Changes page.** File entries now show sizes (added: size, removed: former size, modified: `old → new (±delta)`), with the directory dimmed and the file name emphasized; headline tiles add total **size change**, **GameObject delta**, **package changes** and **scene changes**; the timing card shows total files and total size before → after. Very long lists scroll inside their section and start collapsed above 50 entries.
- Site scripts (`search-index.js`, `app.js`) load with `defer`, so a large search index never blocks page parsing.

## [0.6.0] - 2026-07-23

### Added
- **Dark theme for the generated site.** Every page now ships with a light/dark toggle (🌙/☀️) in the sidebar. ## [0.3.0] - 2026-07-22

### Fixed
- Asset pages were unreadable when the UI language was switched to Persian. `app.js` sets `dir="rtl"`, but the value spans holding paths, GUIDs, numbers, enums and type names carried no `direction: ltr` / `unicode-bidi: isolate`, so every piece of Latin data was bidi-reordered into fragments. Only `[data-en]` was isolated; the data itself was not. All data-bearing elements are now explicitly LTR-isolated.
- `.ds-asset-grid` used `minmax(300px, 1fr)`. A grid track floor makes the grid wider than its own container whenever the container is narrower than the floor - which is constant inside a nested folder node - so cards overflowed and overlapped. Now `minmax(min(320px, 100%), 1fr)`, with `min-width: 0` on every grid child.
- `.ds-field-grid` had `96px` + `64px` column floors that overflowed narrow cards; `.ds-asset-card`'s `overflow: hidden` then silently clipped the data, which is why Import Settings looked present but unreadable. Floors removed and a container query stacks the grid when a card is genuinely narrow.
- `.ds-tree ul` added 33px of indentation per nesting level, compounding into the two failures above at depth. Indentation now tapers with depth.
- `.ds-kv-line` was a flex row with a non-shrinkable key, so one long path forced the whole card wider than its grid track. Rebuilt as a two-column grid.
- **"Export Full Project With Files" copied every asset's bytes into `files/` and then never referenced them from any page.** No `physicalFile` key was written to the JSON entry and no renderer emitted `<img>`, `<audio>`, `<video>` or a download link, so images and audio never appeared even after a with-files export. Asset cards now play audio and video inline, show the real image file, and expose Open / Download for every copied asset.
- `ThumbnailGenerator.BlitResize` created its RenderTexture with default read/write. In a Linear color-space project this produced gamma-incorrect (washed out or near-black) thumbnails. It now requests `RenderTextureReadWrite.sRGB` when the project is Linear.
- `AssetDatabase.FindAssets(string.Empty, ...)` is undocumented and returns nothing on some Unity versions, producing a silently empty Assets page. `CollectFilePaths` now walks the filesystem and validates each candidate against the AssetDatabase.
- `SanitizeAnchor` collapsed every non-alphanumeric character to `-`, so `UI_Menu`, `UI/Menu` and `UI Menu` all produced the same DOM id. A stable FNV-1a suffix now keeps them distinct.
- `BuildGuidLookup` resolved a GUID indexed under several folders by last-writer-wins, so cross-links pointed at a different page between runs. Resolution is now deterministic, preferring the most specific page.
- `AssetPageRenderer`'s path map was case-sensitive while the folder tree normalised separators, so case drift dropped files out of the rendered tree. Now `OrdinalIgnoreCase`.
- `.ds-matrix-row-head` used the physical `left` property and broke under RTL. Now `inset-inline-start`.

### Changed
- Thumbnails are written as real `assets_ui/thumbs/<guid>.png` files instead of base64 data URIs inlined into both the HTML and the JSON. Previews now lazy-load and cache; a large project's Asset page is no longer a single multi-hundred-megabyte document. Callers that pass no output root still receive the base64 form.
- Import Settings, Fields, Shader Properties and Prefab Contents render inside a collapsed `<details>`. A closed `<details>` is parsed but never laid out, which is the difference between a folder page opening and a folder page hanging the browser.
- Each folder node renders at most `MaxAssetsRenderedPerFolderNode` (300) asset cards, with a count of the remainder. The complete list always remains in `data/assets_*.json`.
- `.tga`, `.psd`, `.exr`, `.tif`, `.webp` and `.bmp` textures - plus Materials, Prefabs, Models and Fonts - now get Unity's real rendered preview via a short polling wait, instead of falling through to a 16x16 type icon. Icons, when still used, are tagged and sized as small badges rather than stretched across the preview box.
- Every generated URL is percent-encoded per path segment. Asset paths containing spaces or `#` previously produced broken links.
- Full-project exports drive an Editor progress bar. They previously ran with no feedback at all and looked frozen.
- Every export prunes scene and asset pages whose source no longer appears in the manifest, instead of leaving orphaned documents behind forever.

## [0.2.3] - 2026-07-08

### Fixed
- Nested/jagged numeric arrays (vertex lists, matrices, per-bone weight tables, …) could still split a value mid-character (e.g. `0.399261` into `0.39` / `9261`) despite the 0.2.1/0.2.2 fixes, because `.ds-nested-table`'s nested `<table>` and `.ds-array-item`'s `overflow-wrap: anywhere` could still be squeezed into a narrow column once enough levels of nesting compounded a fixed percentage width. The entire field/array rendering pipeline (shared by Asset pages and Scene pages) has been rebuilt instead of patched again: `<table>`-based field rows are replaced by a CSS Grid row layout (`.ds-field-grid`, rows using `display: contents`) that builds its own column tracks from its own available width at every nesting level, so a fixed percentage can no longer compound down through nested structs/components/arrays.

### Changed
- Compact array elements (numbers, bools, enums, vectors, references, …) now render as fixed-width grid cells (`.ds-array-grid` / `.ds-array-cell`) using `white-space: nowrap` + `text-overflow: ellipsis` instead of the old `.ds-array-wrap` / `.ds-array-item` flex-wrap chips - a value either fits or truncates with an ellipsis, and the untruncated value is always available as a hover tooltip.
- `RenderShaderProps` (Material shader property tables) now shares the same field-grid renderer as every other field table instead of its own separate `<table class="ds-field-table">` markup.
- Object reference chips (`.ds-ref-chip`) now truncate with an ellipsis and carry a `title` tooltip with the full target name, instead of wrapping (and potentially breaking mid-character) a long name.

### Added
- Jagged/2D scalar arrays (an array whose own elements are arrays) are now detected and rendered as one real, sticky-header, horizontally+vertically scrollable spreadsheet-style table (`.ds-matrix-scroll` / `.ds-matrix-table`) instead of nesting an array block inside another array block - this specific shape of data was the actual root cause behind the character-splitting bug recurring after every previous patch.
